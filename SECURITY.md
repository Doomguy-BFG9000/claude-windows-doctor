# Security policy

## Supported versions

Security fixes go into the latest release on `main`.

## Reporting a vulnerability

Please do not report a vulnerability in a public issue. Use GitHub's private reporting: [https://github.com/nrzz/claude-windows-doctor/security/advisories/new](https://github.com/nrzz/claude-windows-doctor/security/advisories/new), or the contact in the [nrzz security policy](https://github.com/nrzz/.github/blob/main/SECURITY.md). You can expect a first answer within 72 hours, and credit in the release notes if you want it.

## What this tool does, and does not do

It has no telemetry or account and sends nothing to Anthropic or to anyone else. It has no network code except the local connection of `check --live` (see below).

**It reads.** The settings files that bear on the shell, only for the keys `env`, `defaultShell`, `permissions.deny` and `wslInheritsWindowsSettings`: the user settings in the config folder (`%USERPROFILE%\.claude`, or `CLAUDE_CONFIG_DIR`), the project's `.claude\settings.json` and `.claude\settings.local.json`, and the managed settings (`C:\Program Files\ClaudeCode\managed-settings.json`, its `managed-settings.d` folder, and the `Settings` value under `SOFTWARE\Policies\ClaudeCode` in `HKLM` and `HKCU`). The registry: the values of `HKCU\Environment` (every name; a value only when its name ends in DIR, PATH, HOME, FILE or ROOT, or the value is a switch such as 1 or false), `LongPathsEnabled`, the code pages, and where Git for Windows says it is installed. The folders on PATH and the usual install folders, to find `git`, `bash.exe`, `pwsh`, `powershell` and every `claude`. The project's `.git\index.lock`. Inside WSL, `/proc/version` and the paths of the config folder and the project. No settings file is shown whole, and no environment value is printed unless it is a path or a switch: a token in `ANTHROPIC_API_KEY` shows as "set", never its value.

**It starts a few programs, all of which only read:** `where.exe`, `reg.exe query`, `git --version` and `git config --show-origin --get-all`, `powershell.exe` (or the PowerShell Claude Code would use) with `-NoProfile -NonInteractive` and `Get-ExecutionPolicy -List`, `cmd.exe /c chcp`, `tasklist` (only when an `index.lock` exists), `wsl.exe -l -v`, `npm --version` and `npm config get prefix`, the Git Bash that Claude Code would take with `-c "exit 0"`, and `--version` of each `claude` it finds, in a throwaway home and config folder with no `CLAUDE_*` or `ANTHROPIC_*` variable. It never runs the desktop app's own launcher or a Microsoft Store alias. A program that has a startup cache of its own (PowerShell, npm) may leave it under your `AppData` folder; the tool itself leaves nothing there.

**It writes in two commands only: `fix --git-bash` and `undo`.** They change one value, `CLAUDE_CODE_GIT_BASH_PATH`, in the Windows user environment (`HKCU\Environment`), through `reg.exe`, and then tell running programs that the environment changed (by setting and deleting a throwaway variable, `CLAUDE_WINDOWS_DOCTOR_NOTIFY`, with `setx` and `reg delete`). What was there before is saved first in `<config folder>\windows-doctor\record.json`, written through a temporary file and a rename; if that cannot be written, the user environment is put back as it was. `undo` puts back the old value with its old type, or removes the value, and deletes the record. `--dry-run` shows the change and writes nothing. Both refuse on a system that is not Windows. They never change `PATH`, the machine-wide environment, Git's configuration, the execution policy, a settings file or anything else in the registry. The throwaway folders in the system temp folder where `claude --version` and `check --live` run are removed afterwards.

**`check --live` opens one local connection and starts the real `claude`.** A fake Messages API listens on 127.0.0.1 at a port the system picks; `claude -p` is started with `ANTHROPIC_BASE_URL` pointing at it, a dummy key (`sk-ant-probe`), a throwaway home, config folder and project folder, telemetry, non-essential traffic and automatic updates switched off, and every `CLAUDE_*`, `ANTHROPIC_*` and `CLAUDECODE*` variable of your environment removed. Only the settings that decide the shell are copied into the throwaway config folder (the `env` entries `CLAUDE_CODE_GIT_BASH_PATH` and `CLAUDE_CODE_USE_POWERSHELL_TOOL`, `defaultShell`, the whole-tool deny rules); your hooks, your keys and your other settings are not. The fake API answers every request with the text PROBE-DONE, so no model is reached and no token is spent. The binary is the one on PATH or the one you name with `--claude`: it runs with your user's rights, as it does when you start it.

The findings are a reading of what Claude Code did when it was put to the binary (the README's "What was verified" says which versions); they are not a guard. A wrong verdict is a bug and not a vulnerability: report it as an issue.
